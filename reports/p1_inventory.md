## 3. Báo cáo Bất thường và Tính Nhất quán (Anomaly & Consistency Audit)

Theo quy tắc nghiên cứu, Executor chỉ kiểm kê và ghi nhận đầy đủ hiện trạng, **tuyệt đối không can thiệp hay sửa chữa** dữ liệu thô trong task P1-T1.

### 3.1. File rỗng (Zero Data Rows)
Phát hiện **3 file** chỉ có header `['datetime_utc', '<sensor>']` và không có bất kỳ dòng dữ liệu nào:
- Meter `H2.T.Z33`: file `H2.T.Z33.WQ_raw.csv.gz` (cột: `H2.T.Z33.WQ`)
- Meter `H3.Z41`: file `H3.Z41.WQ_raw.csv.gz` (cột: `H3.Z41.WQ`)
- Meter `H3.Z42`: file `H3.Z42.W_raw.csv.gz` (cột: `H3.Z42.W`)

### 3.2. Dữ liệu Timestamp Trùng lặp (Duplicate Timestamps)
Phát hiện **3 file** chứa các dòng có timestamp lặp lại liên tiếp (tổng cộng 286,446 dòng lặp).
Top các file có số lượng duplicate timestamp đáng chú ý:
- `V.Z84` / `V.Z84.W_out_raw.csv.gz`: **164,405** dòng trùng (3.90%)
- `V.Z84` / `V.Z84.W_raw.csv.gz`: **61,790** dòng trùng (1.45%)
- `V.Z84` / `V.Z84.W_in_raw.csv.gz`: **60,251** dòng trùng (22.36%)

### 3.3. Dữ liệu Sai Thứ tự Thời gian (Out-of-order Timestamps)
- Tất cả các file thô đều được sắp xếp thời gian tăng dần đơn điệu (`out_of_order = 0`).

### 3.4. Schema Inconsistencies & Readability
- **Tính đọc được (Readability)**: 1,603 / 1,603 file (`100%`) giải nén và phân tích CSV thành công mà không gặp bất kỳ lỗi IO hoặc corrupt gzip nào.
- **Tính nhất quán schema**: 100% file đo lường đều có đúng 2 cột, cột đầu tiên là `datetime_utc` tuân thủ định dạng ISO 8601 kèm múi giờ `+00:00`.

### 3.5. Các Thực thể Đặc biệt Cần Lưu ý Trong Quá trình ETL
1. **Meter `V.ZE84` (Inverted CT Corrections)**:
   - Chứa 21 file mang hậu tố `_corrected_raw.csv.gz` bên cạnh 21 file `_raw.csv.gz`.
   - Đây là dấu vết hiệu chỉnh cảm biến CT bị ngược pha được thực hiện tại nguồn.
   - Tuân thủ Protocol: **Không dùng `_corrected_raw` làm Ground Truth**.
2. **Thư mục `data/V.Z84/backup/`**:
   - Chứa 2 file `V.Z84.W_in_raw.csv.gz` và `V.Z84.W_out_raw.csv.gz`.
   - Đã được phân lập khỏi danh sách 1,603 file đo lường chính thức để tránh trùng lặp.
3. **Tỷ lệ NaN trong Raw Data**:
   - Số lượng NaN rõ ràng trong raw là **0** hoặc rất ít; missingness trong smart-meter raw data thực chất xuất hiện dưới dạng **gaps trong chuỗi thời gian** (không phát tín hiệu đọc).
   - Vấn đề này sẽ được giải quyết triệt để tại bước `P1-T3` (chuẩn hóa lưới 15 phút và reindex bảo toàn NaN gốc).
